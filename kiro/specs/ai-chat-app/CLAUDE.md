# AI チャットアプリケーション 開発仕様書 - 司令塔ドキュメント

## 概要
このドキュメントは、OpenAI GPT-4 APIを活用したAIチャットアプリケーションの開発における司令塔として機能します。Claude Code等のAI開発ツールが迷わず適切な実装を行えるよう、すべての設計書への参照と開発指針を提供します。

## プロジェクト基本情報

### 技術スタック
- **フロントエンド**: Next.js 15.x (App Router) + TypeScript
- **バックエンド**: Python Flask 3.x + OpenAI SDK
- **デプロイ**: Fly.io (Docker)
- **開発環境**: Windows ローカル + GitHub

## 🚨 AI開発ツール向け重要指針

### 🛑 実装前の必須確認事項
**⚠️ 重要: 勝手に実装を開始してはいけません**

1. **現在の実装状況を正として扱う**
   - 既存のコードは完全に動作する状態です
   - 「足りない」「不完全」と判断して勝手に追加実装しないでください
   - 設計書の「将来拡張予定」は現在実装する必要がありません

2. **実装指示の明確化**
   - **tasks.md のタスクのみ実装対象**です
   - 設計書を読んで「これも必要だろう」と判断しないでください
   - 明示的な指示がない限り、新機能は実装しないでください

3. **段階的改善の原則**
   - 現在動作している機能を壊さないことが最優先
   - リファクタリングは段階的に実行
   - 一度に大きな変更を行わない

### 📋 実装作業の進め方

#### ステップ1: タスク確認
- `tasks.md` から具体的なタスクを選択
- タスクの詳細と現在の問題を理解
- 影響範囲を確認

#### ステップ2: 設計書参照
- 該当する設計書を参照（必要な場合のみ）
- 現在の実装状況を確認
- 将来拡張予定は参考程度に留める

#### ステップ3: 実装実行
- 最小限の変更で目的を達成
- 既存機能の動作を保証
- テストで動作確認

### 🚫 やってはいけないこと

1. **勝手な機能追加**
   - 認証機能の実装
   - データベース機能の実装
   - セッション管理機能の実装
   - 存在しないAPIエンドポイントの実装

2. **大規模なリファクタリング**
   - 全体的なアーキテクチャ変更
   - ファイル構造の大幅変更
   - 複数機能の同時変更

3. **設計書の独自解釈**
   - 「こうあるべき」という判断での実装
   - 将来拡張予定の先行実装
   - 設計書の不足部分の補完

### ✅ 実装対象の判断基準

#### 実装してよいもの
- `tasks.md` に明記されたタスク
- 明示的な指示があるリファクタリング
- 既存機能の改善（動作を保証する範囲）

#### 実装してはいけないもの
- 設計書にあるが現在のコードにない機能
- 「将来拡張予定」と明記された機能
- 指示されていない新機能

## 🔄 作業フロー

### 標準的な作業手順
1. **CLAUDE.md を最初に読む**（このドキュメント）
2. **tasks.md から実装タスクを選択**
3. **必要に応じて関連設計書を参照**
4. **最小限の変更で実装**
5. **動作確認・テスト**

### 質問・確認が必要な場合
- タスクの詳細が不明な場合
- 既存機能への影響が不明な場合
- 実装方針に迷いがある場合

**→ 勝手に判断せず、必ず確認を求めてください**
